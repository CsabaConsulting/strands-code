<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv→CLI (`--session-id`) | Untrusted CLI input flows into the SDK session identifier |
| REPL input→agent | Freeform user text becomes agent content, never executed by the CLI |
| snapshot files at rest | Conversation data (may contain secrets) sits on local disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | main.py `--session-id` handling | high | mitigate | Pass the id through SDK validate_identifier; catch ValueError and show a usage error instead of crashing; add a negative test with `--session-id ../../x`. BLOCKING until green. |
| T-01-02 | Tampering | session snapshot files | medium | mitigate | Rely on SDK storage symlink guards; never follow or create symlinks in session_index; verify LocalFileStorage perms at implementation (RESEARCH A8). |
| T-01-03 | Information disclosure | session dir at rest | medium | mitigate | Create session/index dirs with restrictive perms (0o700); never log transcript content. |
| T-01-04 | Spoofing | resumed transcript | low | accept | Resumed content is trusted-to-self in Phase 1; prompt-injection hardening is Phase 3 scope. |
</threat_model>
