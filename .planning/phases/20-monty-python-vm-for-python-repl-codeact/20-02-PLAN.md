# Plan 20-02: 3-Site CLI Migration, CodeAct Callback Security Parity & Deterministic Teardown

<objective>
Migrate all 3 CLI `python_repl` peer sites (`entry/main.py`, `policy/codeact.py`, and `loop/btw.py` / `entry/subagent.py`) onto `MontyPythonInterpreter` (`D-03`), wire deterministic session teardown across reset, loop exit, `/btw` exit, and subagent exit (`D-09`), and backport Phase 19.1 symlink, sensitive-read, protected-path, and `PolicyConfig` `[[deny]]` enforcement into `codeact_read`, `codeact_write`, `codeact_edit`, and `codeact_shell` (`D-07`, `D-08`).

Purpose: Eliminate the last in-process `smolagents` execution in `strands_code_cli/`, ensure dynamic CodeAct runtime arguments cannot bypass Phase 19.1's security floor, and prevent leaked worker subprocesses across REPL resets and delegates.
</objective>

## Security & Reliability Threats (ASVS L1)

| ID | Threat | Mitigation in Plan 20-02 |
| :--- | :--- | :--- |
| `T-20-05` | Dynamic CodeAct calls (`read('.env')`, `write('.agent/policy.toml', ...)`, symlink/tilde traversal, FIFO/non-regular file reads) bypassing pre-turn static checks | Enforce `_prepare_codeact_path()` (pre/post-resolve symlink refusal, `~` expansion before resolve, `_is_sensitive_read_path`, `_is_protected_skills_or_config_path`) + `O_NOFOLLOW | O_NONBLOCK` regular-file read + `atomic_write_text(..., mode=None)` (`D-07`) |
| `T-20-06` | Dynamic CodeAct `read`/`write`/`edit`/`shell` calls bypassing active `PolicyConfig` `[[deny]]` rules or reading symlinked repo policies | Load `PolicyConfig.load(repo_path=base / ".agent" / "policy.toml")` fail-closed and evaluate `decide(op, ..., policy, cwd=base)` inside every CodeAct host callback (`D-08`), returning refusal strings without prompting |
| `T-20-07` | Leaked Monty worker sessions or state bleed across `CodeactStint`, main `python_repl`, `/btw`, `subagent`, and loop exit | Isolate per-instance `MontyPythonInterpreter` sessions; close deterministically in `CodeactStint.reset()`/`close()`, `_close_loop_session()`, `_teardown_btw_agent()`, and subagent child cleanup (`D-03`, `D-09`) |
</threat_model>
