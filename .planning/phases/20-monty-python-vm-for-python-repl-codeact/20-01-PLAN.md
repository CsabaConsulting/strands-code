## Security & Reliability Threats (ASVS L1)

| ID | Threat | Mitigation in Plan 20-01 |
| :--- | :--- | :--- |
| `T-20-01` | Untrusted AI-generated Python tampering with CLI host memory, exhausting host RAM, or hanging infinitely in-process | Execute in subprocess-isolated Rust VM (`pydantic-monty` `Monty` worker pool) with `256 MiB` `max_memory`, `60s` `max_feed_duration_secs`, and `200` recursion limit (`D-05`, `D-06`) |
| `T-20-02` | Silent security downgrade to in-process `smolagents` if `pydantic-monty` or `monty` binary is absent or fails to spawn | Fail closed inside `MontyPythonInterpreter` returning explicit `STDERR` error without importing `smolagents` (`D-02`) |
| `T-20-03` | `os` / `pathlib` / `subprocess` import attempts inside VM or ambient `MONTY_BIN` leaking into non-integration tests | Enforce `os=None` inside Monty plus fail-closed AST import gate (`os`, `pathlib`, `subprocess`, `__import__`, `importlib`) returning `"not allowed"` (`D-04`); add `"MONTY_BIN"` to `tests/conftest.py` `_PROVIDER_ENV_VARS` |
| `T-20-04` | Runaway `print()` stdout loop exhausting host memory or orphaned worker subprocesses after reset/exit | Cap `print_callback` accumulation at `4 MiB` with clean truncation note (`D-05`); track and close sessions deterministically + `atexit` `shutdown_shared_pool()` (`D-09`) |
</threat_model>
