## 1. Upstream `strands-agents 1.66.0` & `strands-harness 0.5.0` Findings (`D-01`, `D-08`)

### 1.1 Hook Execution Order & `event.cancel_tool` Visibility
- `HookOrder` (`strands/hooks/registry.py:31-42`): `SDK_FIRST = -100`, `INTERVENTION_OUTPUT = -90`, `DEFAULT = 0`, `MODEL_ROUTING = 50`, `INTERVENTION_INPUT = 90`, `SDK_LAST = 100`. Lower values execute first (`HookRegistry.add_callback` inserts sorted by `order` at `:279`; `get_callbacks_for` iterates ascending at `:466`).
- Steering registers at `HookOrder.SDK_FIRST` (`strands_code_cli/loop/steering.py:312-314`).
- `InterventionRegistry._register_hooks` (`strands/interventions/registry.py:72-77`) registers `_on_before_tool_call` on `BeforeToolCallEvent` at `HookOrder.INTERVENTION_INPUT` (`90`).
- **Live-verified end-to-end with `Agent` + `ToolCallingModel`:**
  1. Steering hook (`-100`) runs first and sets `event.cancel_tool = "Steering redirected by user: ..."`.
  2. `InterventionRegistry._on_before_tool_call` (`90`) runs second (`BeforeToolCallEvent._can_write` includes `cancel_tool` at `strands/hooks/events.py:244-245`, and `_dispatch` does NOT skip when `cancel_tool` is truthy), so `PolicyGateHandler.before_tool_call(event)` observes `event.cancel_tool` ALREADY populated.
  3. Returning `Proceed(reason="steering-redirected")` leaves `event.cancel_tool` untouched (`_apply_before_tool_call` returns `False` at `registry.py:148-149`).
  4. `ToolExecutor._stream` (`strands/tools/executors/_executor.py:252-277`) emits `ToolCancelEvent` + error `ToolResult`, runs `AfterToolCallEvent`, and skips tool execution cleanly.
- **Result:** `SteeringState.arm` / `consume_arm`, `SteeringSlot.consume_arm`, and `bind_steering` are 100% obsolete and can be cleanly deleted.

### 1.2 `InterventionHandler` Method Shape, `Deny(reason)`, and `on_error="throw"` Trap
- **Class-level override required:** `InterventionRegistry._is_overridden` (`registry.py:59-63`) compares `getattr(type(handler), method, None) is not getattr(InterventionHandler, method, None)`. `PolicyGateHandler.before_tool_call` MUST be defined on the class and `name = "strands-code:policy-gate"` defined cleanly (`strands_harness/interventions.py:68-80` & `InterventionRegistry.__init__` reject duplicate names with `ValueError`).
- **`async def before_tool_call` for test + SDK compatibility:** `InterventionRegistry._dispatch` (`registry.py:213-215`) awaits any awaitable returned by `before_tool_call`. Using `async def before_tool_call(self, event: Any, **kwargs: Any) -> Proceed | Deny:` matches `HumanInTheLoop.before_tool_call` (`hitl.py:235`), works natively with SDK async execution AND preserves direct `asyncio.run(handler.before_tool_call(event))` test calls (`test_policy_gate.py`, `test_broker.py`, `test_mode.py`, `test_diff_gate.py`, `test_choice.py`).
- **`Proceed()` vs `Deny(reason)`:**
  - `Proceed()` is a no-op; `reason` is internal metadata only (`registry.py:148-149`).
  - `Deny(reason=...)` sets `event.cancel_tool = f"DENIED: {action.reason}"` (`registry.py:128-130`) and short-circuits remaining handlers. No `"DENY:"` smuggling is needed inside `PolicyGateHandler`.
- **CRITICAL `on_error` / `TurnCancelled` trap:**
  - `InterventionHandler.on_error` (`handler.py:76-79`) defaults to `"throw"`. Setting `on_error = "deny"` would cause `InterventionRegistry._dispatch` (`registry.py:220-223, 250-267`) to swallow `TurnCancelled` (Ctrl-C) into `Deny("Handler threw: ...")`!
  - **Rule:** Keep `on_error = "throw"` on `PolicyGateHandler`, explicitly re-raise `(TurnCancelled, KeyboardInterrupt)` inside `before_tool_call`, and catch general `Exception` internally to return `Deny(reason="Approval gate failed closed — skipped, continuing.")`.
