## Round 1: 6 Atomic Hardening Decisions (`D-03`–`D-08`)

### Q1: Unboxed `read` Scope Verdict (`D-03`)

Once `read` runs through `PolicyGateHandler` instead of `allowed_tools`, how should unboxed `read` behave on paths outside `effective_roots` (`cwd`, `/tmp`, `[[allow]]` read roots)?

| Option | Description | Selected |
|--------|-------------|----------|
| *(Recommended)* Prompt on outside-scope `read` (keep `[[deny]]` hard-deny) | In-scope reads (`cwd`, `/tmp`, `[[allow]]` read roots) stay silent; outside-scope reads prompt `[y/n/always/never]`. | ✓ |
| Hard-deny outside-scope `read` | Exact parity with `write`/`edit`: refuse any `read` outside `effective_roots` unless covered by `[[allow]] tool="read"`. | |
| Keep unboxed `read` unscoped (`[[deny]]` only) | ⚠️ Breaks confinement parity with `search`/`write`/`edit` and leaves `~/.ssh/*` readable unless explicitly denied. | |

**User's choice:** Prompt on outside-scope `read` (keep `[[deny]]` hard-deny) — in-scope reads (`cwd`, `/tmp`, `[[allow]]` read roots) stay silent; outside-scope reads prompt `[y/n/always/never]`.

### Q2: Sensitive-File Read Downgrade & Protected Paths (`D-03`)

Should the expanded protected-path `Prompt` downgrade (disabling `Always`) also cover `read` of sensitive secret files (`.env`, `.env.*`, `~/.ssh/*`, `~/.aws/*`), or apply to `write`/`edit` only?

| Option | Description | Selected |
|--------|-------------|----------|
| *(Recommended)* Also prompt on `read` of sensitive secret files (`.env`, `.env.*`, `~/.ssh/*`, `~/.aws/*`) | Matches Strands Box Dogwood's secret-read floor even when unboxed (`Always` disabled). | ✓ |
| Protected-path downgrade on `write`/`edit` only | Expand `write`/`edit` protection to `.agent/**`, `.git/**`, `.env*`, `STRANDS.md` & host dirs, leaving in-repo `.env*` reads silent unless in `[[deny]]` (⚠️ Breaks unboxed parity with Dogwood). | |

**User's choice:** Also prompt on `read` of sensitive secret files (`.env`, `.env.*`, `~/.ssh/*`, `~/.aws/*`) with `Always` disabled — matching Dogwood's secret-read floor even when unboxed.

### Q5: File Modes for Private vs Git-Tracked Repo Files (`D-06`)

| Option | Description | Selected |
|--------|-------------|----------|
| *(Recommended)* Private files `0o600`; git-tracked repo files (`STRANDS.md`, `.agent/skills-lock.json`) standard readable (`0o644` masked by umask) | Protects secrets/traces/configs while avoiding surprising `0600` modes on committed repo files. | ✓ |

**User's choice:** Private files `0o600`; git-tracked repo files (`STRANDS.md`, `.agent/skills-lock.json`) standard readable (`0o644` masked by umask).
