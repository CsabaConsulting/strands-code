# Plan 21-02: `@file` / `/file` Gitignore-Aware Fuzzy Picker, Fail-Closed Attachment Builder & Post-Routing Media Gate

<objective>
Implement `@file` inline attachment resolution, gitignore-filtered fuzzy completion, `/file` TTY picker prompt pre-fill, fail-closed filesystem/policy/size bounds, and post-routing `supports_media` verification (`TOOL-05`, `D-03`–`D-06`).

Purpose: Let users reference workspace files with `@path` or `/file` cleanly across text, source code, images, and binary documents with full `read`/`codeact_read` security parity, post-routing model media gating, and `run_loop` complexity discipline (`CC <= 18`).
</objective>

<threat_model>
## Security & Reliability Threats (ASVS L1)

| ID | Threat | Mitigation in Plan 21-02 |
| :--- | :--- | :--- |
| `T-21-04` | Arbitrary file read, symlink escape, TOCTOU FIFO/device open, sensitive secret exfil (`.env*`, `.ssh`, `.aws`), or `[[deny]]` bypass via `@path` / `/file` | Reuse `policy/scope.py` (`effective_roots(cwd, policy, tool_name="read")`, `confine`), `policy/codeact.py` un-collapsed symlink-traversal + `PolicyConfig.load` checks, `refuse_symlink_under_roots`, `_is_sensitive_read_path`, `decide("read")`, `O_NOFOLLOW | O_NONBLOCK`, `stat.S_ISREG`, and filter symlinks/secrets out of discovery (`D-05`) |
| `T-21-05` | Memory / context DoS via giant files, >4 MiB attachments, binary floods, or too many attached files | Enforce `4 MiB` per-file cap (`CODEACT_MAX_FILE_BYTES`), `16 MiB` total turn cap, `8` max attachments, and fail clearly on non-UTF-8 unknown binary extensions (`D-05`) |
| `T-21-06` | Binary attachments crash media-less routed model, leak into `/route`, inject control chars via document names, or craft `"toolUse"` blocks | Evaluate `supports_media(current_model)` **after** `_route_pre_turn` on raw ask text; abort turn with actionable error when `False`; sanitize Bedrock `document.name`; pass final list through `validate_content_blocks()` (`D-04`, `D-06`) |
| `T-21-07` | False-positive errors on `@dataclass` / `@pytest.mark` code tokens or expansion of `@path` inside skill instructions / system prefixes | Resolve ONLY tokens where candidate path exists (or explicitly triggers symlink/secret/deny violation); scan ONLY `raw_ask`, never `PLAN_PREFIX`, `CODEACT_PREFIX`, skill bodies, or `/review` diffs (`D-04`) |
</threat_model>
