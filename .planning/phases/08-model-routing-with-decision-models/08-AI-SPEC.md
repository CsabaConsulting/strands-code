## 1. System Classification

**System Type:** Extraction (typed decision calls returning probability tables)

**Description:**
Per ask, the CLI routes to the right model and thinking budget via a cheap decision model through true Decision APIs (OpenRouter `/api/alpha/decisions`, Ollama `/v1/systemone`), with manual override kept. "Good" means the right model serves each ask, low-confidence picks hold instead of guessing, and every routing action is visible in the transcript and `/cost`.

**Critical Failure Modes:**
1. A heuristic or guessed pick routes an ask (models-only: decide → hold, never invent).
2. A low-confidence pick routes instead of holding (threshold gate must hold).
3. Routing overrides an explicit manual `/model` choice.
4. Decision-call failures crash or stall the turn instead of holding current.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** developer tooling (coding CLI)

**User Population:** Software developers issuing per-ask coding requests (implement, refactor, explain, debug) in an interactive terminal session, including `/btw` side questions mid-task.

**Stakes Level:** Medium

**Output Consequence:** The picked model + thinking budget serves the ask: a right pick yields correct code at fair cost/latency; a wrong pick yields wasted spend (over-route), plausible-but-wrong code from an under-powered model (under-route), or lost user trust when the switch is silent or overrides an explicit `/model` choice. Downstream the generated code may be committed and pushed, so misroutes compound into review/rework cost.

### What Domain Experts Evaluate Against

```
Dimension: Right-sized model pick
Good: A deep refactor / multi-file change lands on a capable large-tier model; a one-line lookup or trivial edit lands on a cheap small-tier model
Bad: A short-but-deep ask ("fix the auth race") is sent to the cheapest model because the ask text is short
Stakes: High
Source: Practitioner knowledge — RouteLLM line of work: 50% cost at ~94% quality is achievable only when hard queries still reach the strong model; short-ask-means-deep-work skepticism is locked in CONTEXT D-08
```

```
Dimension: Cost discipline on easy asks
Good: Trivial asks consistently land on the cheapest capable candidate; near-tie probabilities resolve to the cheaper candidate with a visible tie-break note
Bad: Most traffic drifts to the premium model (over-routing) with no per-ask savings visible in `/cost`
Stakes: Medium
Source: Production routing practice — track routing distribution per tier with a target % per tier; over-routing is the standard cost-bleed failure mode
```

```
Dimension: Decision visibility (no silent misroutes)
Good: Every routed ask logs one transcript line (choice + both confidences + ~$/ask delta) and a compact `/cost` entry; hold/pause outcomes get distinct notes
Bad: The model serving an ask differs from what the user expects with no transcript trace, or a routing failure surfaces only as degraded answer quality
Stakes: High
Source: Coding-CLI practitioner norm — full transparency of every routing decision (choice, confidence, fallback indicator); silent quality collapse is the characteristic production failure
```

```
Dimension: Override respect (manual control always wins)
Good: An explicit `/model` choice is never re-pointed by the router; re-enabling routing requires an explicit user action after override
Bad: Routing silently re-routes an ask after the user pinned a model, or flips the model mid-turn
Stakes: Critical
Source: Project constraint (REQUIREMENTS out-of-scope: fully automatic routing with no override is locked out); coding-CLI convention that explicit user instructions override any routing policy
```

```
Dimension: Hold discipline under uncertainty
Good: A below-threshold model pick holds the current model, retries next ask, and notes the reason (e.g. `Routing held (confidence 41% < 70%)`); decision-API failures pause routing instead of guessing
Bad: A low-confidence or failed decision call still routes the ask to a guessed pick, or a heuristic fills in when the decision model is unreachable
Stakes: High
Source: Practitioner fail-safe norm — on router failure degrade gracefully (hold/fail open to a safe known state), never invent a pick; CONTEXT D-08/D-16
```

### Known Failure Modes in This Domain

1. **Under-routing (hard ask → cheap model):** A semantically hard ask misclassified as easy is served by a small model that returns plausible-but-subtly-wrong code; the failure looks like a normal answer and is caught only in review or CI. Root cause is usually length-as-proxy-for-difficulty or a classifier blind to domain nuance ("semantic drift").
2. **Over-routing / cost bleed (easy ask → premium model):** An over-conservative router sends most traffic to the expensive tier; quality looks fine but per-session spend climbs with no visible benefit. Detectable only via routing-distribution and per-ask `~$/ask` tracking.
3. **Silent routing churn:** The serving model changes ask-to-ask (or mid-task for `/btw` side asks) without transcript notes, so the user cannot explain why answer style/quality shifted and loses trust in the tool.
4. **Override clobber / stale verdict:** Routing re-points after an explicit `/model` pin, or a cached/aliased decision-model verdict routes an ask under a strategy that has since changed — both silently substitute the router's judgment for the user's.

### Regulatory / Compliance Context

None identified for this deployment context. Routing decisions are local session behavior over user-chosen models; no regulated data classification, no automated decision with legal effect. Standard posture applies: decision-call payloads (ask text) sent to the configured engine only (OpenRouter cloud vs Ollama local), API keys outside the repo, no routing telemetry exfiltrated.

## 2. Framework Decision

**Selected Framework:** None — direct Decision-API calls (stdlib `urllib` only)

**Version:** N/A (no framework dependency)

**Rationale:**
Decision APIs are 1–2 typed POST calls returning probability tables plus code-side tie-break/threshold logic. LangChain/LlamaIndex have zero Decision-API support (`/api/alpha/decisions`, `/v1/systemone`) — adopting one adds pure abstraction overhead. Model-agnostic + no-vendor-lock-in + local/self-hosted constraints eliminate provider SDK rows; simplest-surface priority favors the thin typed client. The Strands SDK agent layer stays for turn execution.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain | No Decision-API support; abstraction/latency overhead; violates simplest-surface priority (revisit if routing grows chains/memory) |
| Provider SDKs (OpenAI/Anthropic) | Vendor lock-in; no decision-endpoint coverage |

**Vendor Lock-In Accepted:** No — OpenRouter default, Ollama local alternative, Bedrock future; no provider SDK.

### Entry Point Pattern
```python
import json
import os
import urllib.request

def decide(model, state, questions, *, base_url, api_key=None, timeout_s=30.0):
    """POST one Decision-API request; returns the parsed response dict."""
    payload = json.dumps({"model": model, "state": state, "questions": questions}).encode()
    headers = {"Content-Type": "application/json"}
    if api_key:
        headers["Authorization"] = f"Bearer {api_key}"
    req = urllib.request.Request(base_url, data=payload, method="POST", headers=headers)
    with urllib.request.urlopen(req, timeout=timeout_s) as resp:
        return json.loads(resp.read().decode())

# OpenRouter (default engine). VERIFY the model id against the live catalog
# (GET /api/v1/models?output_modalities=decisions) at implementation time and pin the versioned id.
resp = decide(
    "typesafe/jev-1.13",
    {"ask": "Refactor auth middleware to async", "directives": "trivial asks go cheap, deep refactors go big", "side": False},
    {"pick_model": {
        "type": "choice",
        "instructions": "Which candidate model should serve this ask? Judge the ask, not its length.",
        "criteria": {"sol": "Cheapest small model for trivial asks",
                      "terra": "Mid-size model for everyday work",
                      "luna": "Premium large model for deep refactors"}}},
    base_url="https://openrouter.ai/api/alpha/decisions",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
print(resp["model"], resp["answers"]["pick_model"]["choice"])
# Ollama (local engine): base_url="http://localhost:11434/v1/systemone", model="nimble", api_key=None.
```

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `state` | The evidence the model judges: string, object, or array. Minimal — only fields a question reads | Every call: the ask text + directives + side flag (D-07) |
| `questions` | Named typed questions over the shared state; evaluated independently and in parallel, answers invisible to each other | One `choice` per call; a second sequential call only because call 2's options depend on call 1's answer (D-15) |
| `choice` | Primitive picking one option from a defined set; returns `choice`, per-option `probabilities`, `confidence` | Model pick (call 1) and effort pick (call 2) |
| `criteria` | Option key → description prose; reads as an extension of `instructions` | Candidate criteria from D-02 descriptors; effort-level descriptions in call 2 |
| `confidence` | Distribution concentration `1 - H(p)/ln(N)` (0 = uniform, ~1 = one option dominates); NOT calibrated correctness | Logged on the transcript line (D-12); the model-confidence gate (D-16) compares the pick's probability/confidence against `confidence_threshold` |
| Model pin | `canonical_slug` or versioned `id` in one config value, never an alias; response `model` names the dated snapshot that served the request | Strategy config; log the response `model` string with every answer |
| `usage` | `{input_tokens, output_tokens, cost}` (OpenRouter; `cost` in USD). Ollama returns token counts only | `/cost` decision-spend entry (D-12) |
| Engines | OpenRouter `POST /api/alpha/decisions` (Bearer key) vs Ollama `POST /v1/systemone` (no key, local) | Default → local fallback chain (D-08/D-09); same `state`+`questions` shape on both |

### Common Pitfalls
1. **Calling a decision model through a chat endpoint.** On Ollama, decision models MUST be called via `/v1/systemone` — `/api/chat` produces filler-token runaway (observed: 2250 empty tokens to context exhaustion). Same rule on OpenRouter: `/api/alpha/decisions`, never chat completions.
2. **Reading `confidence` as "probability the answer is right."** It measures how concentrated the distribution is, not whether the action is safe. A `noul` near 0.5 means yes/no are equally likely, not "medium". Set `confidence_threshold`/`tie_margin` from real probes (step 7 of the skill), never from round numbers.
3. **Sending quantities to the model.** Prices, context windows, benchmarks, dates-as-ordered-values, arithmetic, negation, and multi-hop indirection all stay code-side. The model judges; code computes. Cost words ("cheapest") ride in criteria prose; almanac prices decide "cheaper" in the tie-break (D-14).
4. **Assuming thresholds transfer.** A threshold calibrated on one model or one question does not carry to another model or question type. Pin the versioned model id (aliases shift probabilities silently) and re-probe on any model change.
5. **Splitting one judgment across questions in a single request.** Question keys are for code and are never sent to the model; parallel questions cannot see each other's answers. The effort question depends on the model answer, so it MUST be a second sequential call (D-15) — never two questions in one request.
6. **Exceeding the `choice` option cap.** The skill/CONTEXT state 2–26 options; Ollama's OpenAPI allows up to 255 for `choice` (2–26 for `score`), and third-party Jev reports say up to 255. The cap is model-dependent — verify against the live API at implementation time and enforce a code-side candidate cap regardless (planner item: cap candidates, tiered pre-filter, or paged choices).
7. **Oversized state on Ollama.** Requests without images must fit 64 KiB and are never truncated; oversize yields 413. Keep `state` to ask + directives + flags, and truncate long asks code-side with a note.
8. **Retrying 4xx or re-asking settled facts.** 400/401/402/403/404 mean the request, key, credits, or model id are wrong — retrying the same call cannot help; hold current and surface. Likewise, values code already holds (current model, strategy knobs) are never re-asked of the model.

## 4. Implementation Guidance

**Model Configuration:**
Decision model pinned from the live catalog at implementation time via `GET /api/v1/models?output_modalities=decisions` (19 models observed 2026-10-11, incl. `typesafe/jev-1.13` and `microsoft/microsoft-decision-1` — re-verify, never hardcode from memory). Selection bar per the skill: context length holds real state with room to spare, price fits per-ask volume, provider footprint fits availability; break ties by probing every candidate on the step-7 probe set. Pin the versioned `id` (or `canonical_slug`) in one strategy-config value — never an alias such as `~typesafe/jev-latest`. Local alternative: `nimble` (or `tev1`/`clef`) via Ollama >= 0.35. Decision models take NO sampling parameters — no temperature, no max_tokens, no system prompt, no streaming, no tools (Ollama: "generation controls are not supported"). Transport knobs only: per-call timeout (observed ~0.4s OpenRouter, ~2.7s local CPU — set timeouts with headroom, e.g. 10s cloud / 60s local, then tune from probes) and max 1 retry on 5xx/timeout/429/502/503/524/529; never retry 4xx — hold current instead.

**Core Pattern:**
Two sequential `choice` calls per routed ask (D-15), gated entirely in code. Call 1 picks the model from strategy candidates; call 2 picks the thinking level over only the picked model's advertised levels (single-candidate strategies skip call 1 but still ask call 2). Code applies the confidence gate, the tie-margin cheaper-substitution, and the hold-current fallback — the model only ever returns probability tables.
```python
# Pre-turn at idle (loop.py), routing on + strategy configured + no manual override.
def route_ask(ask, *, side, strategy, engines):
    state = {"ask": ask, "directives": strategy.directives, "side": side}
    # Call 1: model choice (skipped when len(candidates) == 1).
    if len(strategy.candidates) > 1:
        table = engines.decide("pick_model", state, model_criteria(strategy))  # full prob table
        pick = gate_model(table, strategy)   # threshold + tie_margin; returns pick or HOLD
        if pick is HOLD:
            return hold_current(reason=pick.reason)  # distinct note, retry next ask (D-16)
    else:
        pick, table = strategy.candidates[0], None
    # Call 2: effort choice over the picked model's levels only.
    effort_table = engines.decide("pick_effort", state, effort_criteria(pick))
    effort = top_choice(effort_table)  # weak effort read still routes (D-16)
    return routed(pick, effort, model_table=table, effort_table=effort_table)

def gate_model(table, strategy):
    top, second = top_two(table.probabilities)
    if table[top] < strategy.confidence_threshold:   # named constant from probes
        return HOLD(f"confidence {table[top]:.0%} < {strategy.confidence_threshold:.0%}")
    if table[top] - table[second] <= strategy.tie_margin:  # near-tie: substitute cheaper
        cheaper = min([top, second], key=almanac_price)     # almanac decides "cheaper" (D-14)
        return pick(cheaper, tie_break_note=(top != cheaper))
    return pick(top)
```
Every threshold is a named strategy knob with the cost of each mistake documented next to it; every routed ask logs one transcript line (choice + both confidences + `~$/ask` delta) and a `/cost` entry (D-12).

**Tool Use:**
No framework tools and no provider SDKs — `urllib` POSTs only (see Entry Point Pattern). Supporting integrations: (1) strategy loader/validator reading global + workspace files with repo-wins precedence and fail-soft malformed entries (mirror `ProviderConfig`); (2) candidate enumeration for guided setup — OpenRouter chat-model listing for routing candidates plus `output_modalities=decisions` listing for the decision pick, kept separate per D-06; (3) almanac price lookup (`live_pricing.py`) for the tie-break "cheaper" comparison and the `~$/ask` delta; (4) transcript note via `print_plain` and spend accounting via `cost_context.py`; (5) Ollama version preflight (`/api/version` >= 0.35, model pulled) before using the local engine. Optional observability: OpenRouter `session_id` groups related decision calls in Broadcast/private logging without reaching the provider.

**State Management:**
Routing state is session-sticky and in-memory by default (toggle on/off, current model, hold reason for the retry-next-ask note). Persisted state is the strategy file only (candidates + directives + `tie_margin` + `confidence_threshold` + pinned decision-model id), global and per-workspace. Decision-call inputs/outputs are NOT persisted — they live on the transcript line and in `/cost` (full probability table in verbose/debug only). No decision-model conversation memory exists: each call is stateless, so the ask + directives must be re-sent every time; never cache a routing verdict across asks (model availability and strategy can change, and a cached pick would silently override intent).

**Context Window Strategy:**
Decision calls carry no history — state is one ask plus directives plus flags, filtered and truncated in code first. Before calling: (a) confirm the pinned decision model's context length (from the live catalog entry) holds the largest realistic state with room to spare; (b) truncate over-long asks code-side to fit the tighter engine cap (Ollama 64 KiB body, never truncated server-side) and note the truncation; (c) keep directives compact — they ride every call twice (state + question shaping, D-07), so verbose directives tax both latency and accuracy ("unrelated material costs accuracy"). Effort call 2 reuses the same state; it adds no new context.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

Decision APIs already return typed answers — no LLM text to parse — so "structured output" here means validating the response shape before the gate reads it. Validate every response against this contract (Pydantic if it is already in the dependency closure, otherwise dataclasses + explicit checks — do NOT add a dependency for this):
```python
from pydantic import BaseModel, Field

class ChoiceAnswer(BaseModel):
    type: str = "choice"          # must equal "choice"; reject anything else
    choice: str                   # must be a key of probabilities AND a current candidate
    probabilities: dict[str, float]  # each 0..1, must sum to ~1.0
    confidence: float = Field(ge=0.0, le=1.0)

class DecisionResponse(BaseModel):
    model: str                    # resolved dated snapshot — log it with the answer
    answers: dict[str, ChoiceAnswer]
    # usage: {input_tokens, output_tokens, cost?} — cost present on OpenRouter only
```
Extra code-side checks Pydantic cannot express: `choice` is a live candidate (a stale pick after a strategy edit must hold, never route); probabilities sum to 1 within float tolerance; exactly the asked question keys are present. Retry policy on failure: transport errors (5xx/timeout/429/502/503/524/529) get max 1 retry with a short backoff, then engine fallback (OpenRouter → local → hold); schema-validation failures and 4xx get ZERO retries — log the raw payload, hold current, and surface a distinct transcript note. A validation miss is its own outcome (D-08), never a reason to guess a pick.

### Async-First Design

`urllib` is synchronous and blocking (~0.4s cloud, ~2.7s local CPU per call; up to two sequential calls per ask). The routing decision point sits pre-turn at idle in `loop.py`: if the turn loop is async, run the decision call in an executor (`asyncio.to_thread`) so the turn's event loop never blocks; if the loop is synchronous, call directly. The one common mistake is awaiting a blocking `urlopen` inline in an async handler — it stalls every concurrent turn/heartbeat for the full decision latency. Stream vs. await does not apply: Decision APIs return one JSON response per request (streaming explicitly unsupported) — always await the full response, then gate. Fire call 2 only after call 1's gate passes; never parallelise the two calls (call 2's options depend on call 1's answer).

### Prompt Engineering Discipline

There is no system/user split and no few-shot in Decision APIs — the analogues are `instructions` (the judgment + its inclusion/exclusion rules) and `criteria` (the answer space, reading as an extension of the instructions). Per D-07, directives feed every call twice: once as a `state` field, once shaping the question instructions. Rules from the skill: ask about the fact, not the text ("Which candidate model should serve this ask?" — never "Does the ask mention…"); phrase each question so a careful person could answer it from `state` + `instructions` + `criteria` alone; point at nested fields with backticked paths (`` `ask` ``); never use double negatives; include a no-match option when nothing may fit (here the no-match outcome is code-side HOLD, not a `none` criterion — a guessed `none` pick must still hold). Token budget: there is no `max_tokens` — output is a fixed-shape probability table. Bound cost on the input side instead: minimal state, compact directives, truncated asks.

### Context Window Management

No RAG, no conversation memory, no compaction — each decision call is stateless over one ask. The strategy: (1) send only what the questions read (ask + directives + side flag); anything only code uses (strategy knobs, almanac prices, capability sets) stays out and is applied to the returned answer; (2) verify the pinned model's context length against the largest realistic state at setup/validate time, with room to spare; (3) truncate the ask code-side when it exceeds the tighter engine cap and note it on the transcript line — never let the server truncate (Ollama never does; it 413s). Side asks (`/btw`) route through the same state shape with `side: true` so directives can discriminate (D-04); planner decides per-ask call vs derived mechanics within that constraint.

### Cost and Latency Budget

Decision models bill on input tokens; output tokens are free (Jev FAQ). Observed example: 476 input + 70 output tokens cost `usage.cost` = $0.000019992 (~$0.00002/call) — so a fully-routed ask (2 calls) costs roughly $0.00004 in decision spend, dominated by ask + directive length. Ownership of the numbers: read `usage.cost` from every OpenRouter response into `/cost` (never estimate from token counts); Ollama local calls cost $0 but ~2.7s CPU latency each. Latency budget per routed ask: ~0.8s cloud (2 × ~0.4s), ~5.4s local (2 × ~2.7s) — acceptable pre-turn at idle, but single-candidate strategies skip call 1 and long asks should be truncated. Caching: NO semantic cache — a short ask can mean deep work (D-08 skepticism), so near-duplicate asks must still be judged fresh. An exact-match cache keyed on (ask bytes + strategy hash + engine + model pin) within a session is permissible only if the planner proves a repeated identical ask recurs enough to matter; default to no cache. Sub-task routing is inverted here: the decision model IS the cheap model doing the routing, and the expensive generative turn runs once on the picked model — the savings come from landing easy asks on cheap candidates, visible per-ask as the code-computed `~$/ask` delta.

## 5. Evaluation Strategy

### Dimensions

Rubrics start from the Section 1b domain ingredients. Measurement is
code-first: decision outputs are typed probability tables, not prose, so
there is nothing subjective for an LLM judge to score — verdicts are
expert-labeled and checks are deterministic. No LLM judge is used.

| # | Dimension | PASS | FAIL | Measurement | Priority |
|---|-----------|------|------|-------------|----------|
| E1 | Decision schema compliance | Every response validates against the `ChoiceAnswer`/`DecisionResponse` contract: `type == "choice"`, `choice` is a key of `probabilities` AND a live candidate, each probability in 0..1 summing to ~1.0, `confidence` in 0..1, exactly the asked question keys present, response `model` snapshot logged | A malformed table, a stale pick (candidate removed by a strategy edit), or extra/missing question keys reaches the gate or routes an ask | Code: Pydantic/dataclass validator + hermetic pytest fixtures (valid table, stale choice, bad sum, wrong type, unknown keys) | Critical |
| E2 | Right-model choice accuracy on probe asks | Deep refactors / multi-file changes land on the large tier; trivial lookups land on the cheap tier; short-but-deep asks ("fix the auth race") land on a capable tier — matching the expert-labeled verdict per probe ask | A probe ask routes to a tier the expert verdict forbids — especially under-routing a hard ask to the cheapest model because the ask text is short | Code against Human-labeled probe verdicts: `routing/probe.py` runs the labeled set, accuracy = matched / total; target set from probes, tracked per decision-model pin | Critical |
| E3 | Confidence calibration / threshold-gate discipline | A model pick below `confidence_threshold` holds current, retries next ask, and notes the reason (`Routing held (confidence 41% < 70%)`); threshold and tie-margin defaults are set from real probe distributions, never round numbers | A below-threshold pick routes anyway, or a guessed pick routes with no confidence read at all | Code: hermetic gate tests with synthetic tables straddling the threshold; probe-run calibration curve (binned accuracy vs stated confidence) reviewed at implementation and on every decision-model change | Critical |
| E4 | Tie-margin substitution correctness | When top-two probabilities fall within `tie_margin`, code substitutes the cheaper candidate per almanac prices and notes the tie-break on the transcript line; deterministic for the same table + almanac | A near-tie routes to the pricier candidate silently, or the substitution uses model prose ("cheapest") instead of almanac prices | Code: hermetic tests over crafted tables (exact tie, margin boundary ±ε, clear winner) with stubbed almanac; determinism asserted by repeat-run equality | High |
| E5 | Hold determinism / fail-safe fallback | 4xx, schema-validation failures, timeouts-after-retry, and unreachable engines all hold current (or pause routing) with a distinct note; the turn is served by the current model and never crashes or stalls; no heuristic ever invents a pick | Any failure path routes a guessed model, raises to the caller, stalls the turn, or substitutes a heuristic pick when the decision model is unreachable | Code: hermetic fault-injection tests (400/401/402/403/404, 500-then-success, timeout, invalid JSON, connection refused) asserting hold + note + served turn | Critical |
| E6 | Override respect | An explicit `/model` pin is never re-pointed by the router; routing turns off with a warning and re-enables only on explicit user action; no mid-turn or mid-task model flip | Routing re-routes an ask after a manual pin, flips the model mid-turn, or a cached/stale verdict serves under a changed strategy | Code: hermetic tests (pin → route attempt → assert serving model unchanged; re-enable requires explicit command) + uattest r3 toggle round-trip | Critical |
| E7 | Decision visibility (no silent misroutes) | Every routed ask logs one transcript line (choice + BOTH confidences + code-computed `~$/ask` delta) and a compact `/cost` entry (choice, confidences, decision spend); holds, pauses, tie-breaks, and truncations get distinct notes; full probability table available in verbose/debug | The serving model differs from user expectation with no transcript trace, or a routing failure surfaces only as degraded answer quality | Code: transcript-line and `/cost`-entry assertions in hermetic tests (format, both confidences, delta sign) + uattest r2/r3/r4 live confirmation of `Routed →` / `Routed (btw)` lines | High |
| E8 | Cost discipline / routing distribution | Trivial asks consistently land cheap; near-ties resolve cheaper (E4); per-tier routing distribution and per-ask savings stay visible in `/cost` against the expected mix | Traffic drifts to the premium tier with no per-ask savings — quality looks fine but per-session spend climbs (over-routing cost bleed) | Code (offline): distribution + spend aggregation over probe runs and sampled sessions; Human (FinOps/maintainer) review and sign-off | Medium |
| E9 | Decision latency budget | Routed ask completes within budget (~0.8s cloud / ~5.4s local for two calls; single-candidate skips call 1); async turn loops never block on `urlopen` (executor/`to_thread`) | Routing adds multi-second stalls to every ask, or a blocking call freezes concurrent turns/heartbeats | Code: hermetic timing tests with stubbed engines (call counts, skip-call-1 path, executor usage); live latency measured in uattest r2/r3 | Medium |
| E10 | Payload + credential hygiene (safety) | Ask text goes only to the configured engine (OpenRouter cloud vs Ollama local); API keys live in user config/keychain, never in repo or logs; no routing telemetry exfiltrated; `usage.cost` read from the response, never estimated | Keys, ask text, or decision payloads land in the repo, logs, or a third-party endpoint; cost displayed from estimates instead of `usage.cost` | Code: hermetic tests (no key material in saved strategy — uattest r1 asserts this live; endpoint allowlist per engine; `usage.cost` passthrough incl. Ollama cost-absent case) | High |

### Reference Dataset

**Size:** 20 labeled probe asks to start (production bar for this phase: hold at 20+, expand only from real production holds/misroutes — never bulk up with filler).

**Composition:**
- Critical paths (6): trivial lookup → cheap tier; one-line edit → cheap; everyday implement/debug → mid tier; deep refactor → premium tier; multi-file change → premium tier; single-candidate strategy → effort question still asked.
- Edge cases (6): short-but-deep asks x2 ("fix the auth race", "why is this flaky?"); `/btw` side ask with `side: true`; ask mentioning a model name ("use opus for this") — must not leak into the pick; very long ask exceeding the tighter engine cap (truncate + note); borderline ask expected to sit near the threshold (hold-case seed).
- Failure modes (5): below-threshold table → hold with distinct note; 4xx (bad key / unknown model id) → hold, zero retries; 5xx/timeout → 1 retry then engine fallback then hold; schema-invalid payload (stale choice, bad probability sum) → hold + log raw payload; decision engine unreachable offline → pause routing, current model serves.
- Adversarial inputs (3): near-tie table (margin ±ε) → cheaper substitution with note; strategy edited mid-session so a cached shape would go stale (verdicts never cached across asks); ask crafted to look trivial by length but deep by content (length-as-difficulty trap).

**Labeling:**
- Right-model-per-ask verdicts: senior CLI user / maintainer (product owner) labels each probe ask with the acceptable tier set; staff engineer adjudicates borderline asks (short-but-deep, side asks).
- Threshold/tie-margin defaults: set from the probe-run confidence distributions by the implementer, signed off by the Cost/FinOps reviewer (or maintainer wearing the hat) — never round numbers.
- Timeline: seed probes written during implementation alongside `routing/probe.py` (shadow mode over real asks collects candidates); dataset finalized before verify phase; production holds/misroutes sampled back into the set post-launch. No LLM-judge labeling step — verdicts are deterministic code checks against expert labels.

## 6. Guardrails

### Online (Real-Time)

Every online guardrail resolves to hold-current or pause — never to a
guessed pick. All are pure code checks on the typed response, so they
add microseconds, not latency.

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| G1 — Confidence-threshold gate | Model-pick probability below `confidence_threshold` | Hold current model, retry next ask, transcript note (`Routing held (confidence 41% < 70%)`); counts toward the hold-rate metric |
| G2 — Response validation | Schema-invalid table (wrong `type`, stale `choice` not in live candidates, probabilities out of range or not summing to ~1.0, wrong question keys) or non-JSON/transport body | Hold current, log the raw payload, distinct transcript note; zero retries (a validation miss is its own outcome, never a reason to guess) |
| G3 — Manual-override enforcement | Routing decision point reached while a `/model` pin is active or routing toggle is off | Skip decision calls entirely; serve with the pinned/current model; no transcript routing line for the skipped ask |
| G4 — Transport failure handling | 4xx (400/401/402/403/404) on either engine; or 5xx/timeout/429/502/503/524/529 after max 1 retry + engine fallback exhausted | Hold current (4xx: zero retries — the request/key/model id is wrong); unreachable-everywhere pauses routing and serves current; distinct note naming the engine and code |
| G5 — Request-shape guard | Candidate count vs the `choice` option cap (verify live; enforce a code-side cap regardless) or state body vs the tighter engine cap (Ollama 64 KiB, never truncated server-side) | Over-cap candidates: tiered pre-filter / paged choices per planner scope (never silently drop to one); oversized ask: truncate code-side and note the truncation on the transcript line — never let the server 413 |

### Offline (Flywheel)

Batch review over probe runs and sampled session transcripts — feeds
threshold/tie-margin tuning, directive rewrites, and probe-set growth.

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Per-tier routing distribution + per-ask spend | Every probe run; per-session `/cost` Routing aggregates sampled weekly by the Cost/FinOps reviewer | Over-routing (premium-tier share climbing with flat task difficulty) → tighten directives, re-check tie-margin, expand cheap-tier criteria; under-routing (hard asks on cheap tier surfacing in review/CI) → widen premium criteria, add short-but-deep probes |
| Hold rate + hold-reason mix | All holds logged; review reasons (below-threshold vs transport vs validation) per probe run and sampled sessions | Threshold-hold spike → re-probe calibration curve, consider threshold or directive change; transport-hold spike → engine reliability work; validation-hold spike → schema drift or stale-candidate bug, fix before next release |
| Tie-break rate + realized savings | All tie-break substitutions (already noted on transcript lines); aggregate cheaper-savings per probe run | Tie-breaks never firing → margin too tight or prices stale (check almanac layers); tie-breaks firing on most asks → margin too loose, effectively price-routing — retune from probe margins |
| Silent-misroute audit (visibility spot-check) | Maintainer samples transcript lines from real sessions: every routed ask must have its line, both confidences, and a matching `/cost` entry | Missing/garbled lines → transcript-instrumentation bug (fix immediately — invisibility is the characteristic production failure); repeated user `/model` corrections after routes → add the ask shape to the probe set |
| Probe-set accuracy per decision-model pin | Full 20-probe run on every decision-model id change, directive edit, or criteria rewrite (Promptfoo diff in CI) | Accuracy drop vs the pinned baseline → block the model/directive change until verdicts are re-labeled or the regression is explained; alias drift (response `model` snapshot changed under a pinned id) → re-pin to the versioned id and re-probe |
| Decision spend vs routing savings | `usage.cost` totals vs code-computed `~$/ask` savings per probe run and sampled sessions | Decision spend exceeding savings on easy-ask-heavy traffic → shorten directives, truncate asks harder, or restrict routing to multi-candidate strategies |

## 7. Production Monitoring

**Tracing Tool:** The transcript surface (Phoenix override — see Section 5): per-ask transcript lines + `/cost` Routing entries + full probability tables in verbose/debug + `routing/probe.py` JSONL probe logs. No tracing server; nothing leaves the user's machine beyond the configured decision engine.

**Key Metrics to Track:**
1. Route / hold / pause counts per session (from transcript lines; hold-rate = holds / routed asks).
2. Per-tier routing distribution + per-ask `~$/ask` deltas (over/under-routing detection).
3. Decision spend (`usage.cost` summed from `/cost`) vs routing savings.
4. Decision latency p50/p95 per engine (cloud vs local) + call counts per ask (call-1 skip rate).
5. Schema-validation failure count + transport-hold count by engine and status code.

**Alert Thresholds:**
This is a local CLI — there is no pager. "Alerts" are in-product
signals, and every threshold below is initialized from probe runs at
implementation time (concrete numbers ship with the strategy defaults,
not here):
- Hold-rate spike (session hold rate far above the probe baseline) → warning line on the transcript suggesting `/route validate` / threshold review.
- Schema-validation or transport-hold burst (repeated G2/G4 trips in one session) → distinct warning naming the engine + last error; routing pauses rather than burning calls.
- Single-tier collapse (all recent routes landing on one tier) → `/cost` Routing-section flag for the FinOps/maintainer review loop.
- Decision-latency breach (p95 above budget for the active engine) → note on the transcript line with measured latency (uattest r2 asserts this shape live).
- Alias drift (response `model` snapshot differs from the pinned id) → one-time session warning prompting re-pin + re-probe.

**Smart Sampling Strategy:**
Weight human review toward interactions with concerning signals, not
uniform traffic:
- All holds and pauses (reason + confidence + ask shape) — threshold/fallback health.
- All tie-break substitutions — margin tuning signal.
- Near-threshold routes (pick probability within ~10pp above the threshold) — calibration borderline.
- All schema-validation and transport failures (raw payload logged) — drift/reliability signal.
- All `/btw` side asks and all user `/model` corrections within two turns of a route — side-ask and misroute signal.
- Baseline: a small uniform sample of clean routes per review window to catch silent quality collapse (the failure mode where everything looks fine).
Sampling is manual (maintainer transcript review + probe JSONL diffs) at
this phase's scale; promote to scripted aggregation only when session
volume makes eyeballing impractical.
