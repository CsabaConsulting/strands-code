<resolved_open_items>
Planner resolutions. Executor implements exactly these; no re-derivation.

1. Local engine is `decide_via_ollama` posting `{OLLAMA_HOST}/api/chat` with stream false, a JSON object format schema over model/effort/why, and keep_alive 5m; host defaults to `http://127.0.0.1:11434` with the harness `OLLAMA_HOST` default; timeout 30s for cold model load; any failure returns None. Base URL scheme allowlist is http/https only (D-06, D-09).
2. Engine selection: strategy `engine.primary` of `openrouter` tries OpenRouter then local then hold; `local` tries local only then hold; `off` disables routing even when candidates configure. Local runs when `engine.local_model` names a model; without it the local layer is skipped, not failed. No engine cooldown timers: D-08 retry-next-ask wins over the live_pricing cooldown shape (D-08, D-09).
3. Routing event record is a plain dict with ask, side, model, effort, why, engine, input_tokens, output_tokens, held; the loop keeps a session routing_events list; decide returns the pick plus the usage pair parsed from the engine response usage or message eval counts, defaulting to zeros when absent (D-12).
4. cost_report gains an optional routing parameter defaulting to None; with None the output stays byte-identical to today. With events it appends a Routing section with one line per ask (`ask {n}{side}: {model} ({effort}) via {engine} — {why} [held]` plus decision token cost at the decision model id) and folds decision tokens plus cost into the session totals (D-12).
5. `quiet: true` in the strategy suppresses only the routine routed-switch transcript line; hold-current and engine-failure notes always print since they signal breakage, and /cost always carries full detail (D-12).
6. Side routing: the loop `_build` closure runs decide with side true once per spawn before build_btw_agent; on a parsed pick it resolves the routed model handle via resolve_model with the routed effort and sets parent_kwargs model plus effort; on hold or failure it keeps the parent live model with no side note; the routed side decision appends a routing event with side true and prints the routed line prefixed `Routed (btw)`. No re-decision while the side run is live; no worker-thread decisions (D-04, D-05).
7. Catalog descriptions never enter the decision prompt: the candidate table carries ids plus live stats plus tier plus levels only, so third-party /models text cannot steer a pick beyond the exact-id constraint (D-07).
8. Excluded here by locked decision, not deferred silently: the llama.cpp base-URL variant (A-01 unverified; Ollama covers the local engine) and in-ask engine retries (D-08 allows one attempt per engine per ask).
