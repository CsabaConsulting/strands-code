## 2. Specific Inconsistencies, UX Quirks, Dead Code & Output-Safety Gaps

### A. Output-Safety & Thread-Safety Gaps

1. **Rich markup injection via `--session-id` (`loop/core.py:2526`):** `console.print(f"[dim]Session {session_id} — Ctrl-D to exit.[/dim]")` parses Rich markup on user-supplied `session_id`. `_validate_session_id` (`entry/main.py:77–86`) rejects `/` but **accepts `[` and `]`** (`_validate_session_id("a[b]") == "a[b]"`). Should use `print_plain(console, f"Session {session_id} — Ctrl-D to exit.", style="dim")`.
2. **Unsanitized remote HTTP catalog data printed via raw `builtins.print` in `/route setup` (`dispatch/core.py:792–894, 1003, 1089, 1022–1028, 1101`):** `_setup_catalog_entries()` and `_setup_decision_entries()` never strip ANSI/control chars (unlike `memory/marketplace.py:sanitize_display`), and off-tty setup prints `entry['label']` directly with `builtins.print` (`:1003,1089`), bypassing both `print_plain` and `output_context()`.
3. **Raw `builtins.print` on untrusted model/memory/tool text & missing `RENDER_LOCK`:**
   - Memory curate & revise prompts (`loop/core.py:1623–1624, 1760, 1762`) print `proposal.body`, `proposal.section`, revised `block`, and model `summary` with bare `builtins.print(...)`.
   - Steering reader thread (`loop/steering.py:267–268, 273–274`) calls bare `builtins.print` **without holding `RENDER_LOCK`** (unlike `loop/btw.py:412–418`).
   - HITL approval gate (`policy/policy_gate.py:569–712`) uses 12 bare `builtins.print(...)` calls, mixes `console.print(Syntax(...))` (`:601`) and `print_plain` (`:527`), **and** opens `with output_context():` (`:569`) on the SDK worker thread concurrently with the main thread (`loop/core.py:2718`).
4. **Inconsistent `console.print` calls:** `loop/core.py:1832, 2194–2197, 2227, 2230, 2267, 2285–2287, 2290, 2376, 2379, 2453, 2526`; `dispatch/core.py:2581, 2608` borrow `DEFAULT_CODE_AGENT_CALLBACK_HANDLER.console` from `strands_code_agent`; `entry/first_run.py:62` uses `typer.secho(..., fg=RED)`.
